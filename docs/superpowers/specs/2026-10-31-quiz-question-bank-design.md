# ミレバワカル 基本33問とバリエーションの設計

作成日：2026-10-31
状態：問題原稿を作成済み。図・アニメーション・ゲーム画面は未実装。実機確認は未実施。

## 目的と今回の成果物

目の錯覚を使った図や動きを見て、短い問いの4択に答えるゲームを作る。
1プレイは10問。正解数を先に比べ、同点なら10問の合計回答時間を比べる。
最初に異なる33系統の基本問題を1問ずつ具体化し、その後に色・線・配置・問い・正解の組み合わせを増やす。

今回作成するものは、33問分の問い、図の描き方、4つの選択肢に対応する判定値、正解、答え合わせ、派生条件。
実際に動く問題画面と、ランキングへの接続は今回の成果物に含めない。

問題原稿：[`docs/question-bank/questions-v1.md`](../../question-bank/questions-v1.md)
対応データ：[`docs/question-bank/questions-v1.json`](../../question-bank/questions-v1.json)

## ユーザーが指定したこと

- イラストやアニメーションを問題として表示する。
- 4択を10問行う。
- 正確さを優先し、同じ正確さなら回答の速さで比較する。
- 問いは「長いのは？」「大きいのは？」「赤いのは？」など短くする。
- まず33問を作る。
- その後、色や線の配置などを変え、問いと正解のバリエーションも増やす。

## 作り方の比較と採用方針

ユーザー指定に合う「基本33問を先に用意し、確認後に派生を足す」方法を採用する。
最初から全パラメーターを自由に変える方法は、不正解が複数正解へ変わる場合や、錯視が成立しない場合を見分けにくい。
問題をすべて固定画像で増やす方法は、動く問題や答え合わせに必要な寸法を保持しにくい。

この段階では実装方式や描画ライブラリを決定しない。既存の資料はHTML・CSS・JavaScriptで作られており、
後続の実装ではその資料から独立したクイズ用の描画処理と判定を用意する想定。
何を再利用できるかは実装計画で確認する。

## 33系統の内訳と重複の防止

| 分野 | 系統数 |
| --- | ---: |
| 長さ・大きさ | 9 |
| 傾き・形 | 7 |
| 明るさ・暗い点 | 5 |
| 色・色の広がり | 4 |
| 輪郭・境界 | 2 |
| 動き・速さ・位置 | 6 |
| 合計 | 33 |

33個の family_id を出題単位にする。同一プレイで同じ family_id を2回出さない。
名前が異なっても近い出題になる次の組は1系統とする。
ヘリングとヴント、ヘルマン格子ときらめき格子、ホワイトとムンカー。
学術的に同じ現象と断定する意味ではなく、ゲーム用の出題分類である。

## 画面と答えの定義

以下は制作者の提案であり、ユーザーの指定として扱わない。

- A〜Dを付けた4つの対象を示し、4つの回答ボタンから1つを選ぶ。
- 比較対象が分かるよう「中央の円」「横線だけ」などを小さく添える。
- 基本33問では「全部同じ」「わからない」を選択肢にせず、1つの対象だけを正解にする。
- 寸法は描画に使う座標、角度は画面に固定した方向、色は対象内部の最終描画色で定義する。
- 解説や正解表示は計測対象に入れず、終了後に見返せる案とする。

論理寸法は、拡大縮小前の共通の作図用単位を意味する。各候補を表示の都合で個別に拡大縮小しない。
4個の図が入り切らないときは全体を同じ倍率で変える。ラベル、飾り、影、線の太さを正解の寸法へ混ぜない。
天板と曲がった帯の「大きさ」は画面上の面積に限定し、実際の立体の大きさを問わない。

## 基本形の正解を保証する条件

数値の大小を比べる問題では、最大値または最小値を1つにする。
直線・水平・正方形などでは、条件に一致する対象を1つにする。
線や点の有無では、描画する対象の数を1対3にする。
基本データ内の正解位置はAが9問、B・C・Dが各8問。ただしこの一覧の順番でプレイに出題しない。
判定値や正解ラベルを問題画面に表示しない。

「一番赤い」のような連続的で曖昧な色の強さは使わず、「赤いのは？」では赤系1個と、それ以外3個を用意する。
基本形の色はJSONに固定値を持つ。色系統を変える派生では対象色の分類と背景効果を改めて確認する。
「白い」は無彩色であることを含めて内部で定義し、実測の画面輝度と同じだとは主張しない。

バーバーポールの問題は、模様の一部だけでは移動方向が決まらない場合があるため、
縞に固定した小さな印を観察できる区間を設け、その印の移動方向を問う。
フラッシュラグの問題は、実際に最初の印を描いたフレームで点と印の位置を決め、そのフレームを答え合わせ用に保存する。
予定時刻だけで同期したつもりにしない。印の表示中に他の候補が追いつく配置を禁止する。
初回は問題の計測開始から600ミリ秒後、その後1800ミリ秒ごとに全4図で同時に光る。
初回と再提示を待つ時間も回答時間に含める。一度見逃した後も次の提示で判断できるようにする。
点と印が表示領域に収まる位置で提示する。

## 第1段階：33の基本問題

33問は問題原稿と対応データに記載した1つずつの基本形を使う。
基本形だけでも、33系統から重複なしで10系統を選び、順番を変えて出題できる。
出題系統は等確率で取り出す案とし、分野ごとの出題数の固定は行わない。
派生を大量に持つ系統が出やすくならないよう、先に系統を選び、その後にその系統の問題を選ぶ。

図が1つの正解を持つことに加え、4個同時に表示して対象や目印を読めることと、
錯視の題材としての見え方があることを確認する。
錯視が感じられない人の回答を異常と見なさない。錯視量や個人の能力を測定する診断ではない。

## 第2段階：確認したバリエーションを追加

変えるのは、表示位置・対象寸法・背景の配置・線の角度・配色・動きの方向・問い。
背景だけを変えて正解位置を固定する方法に限定しない。
実際の寸法や対象色も変え、正解となる図を変える。

自由な色や角度を無制限に生成せず、最初は確認した組み合わせを登録する。
色の変更で明暗の順が逆になる問題、線がつぶれる問題、窓から目印が消える問題を除外する。
最も近い候補との差が実画面で読めることを確認し、縮小や丸めで同じに見える候補は採用しない。

問いを反転したときは、値と選択肢も再構成する。
例：「線があるのは？」は線あり1・線なし3、「線がないのは？」は線なし1・線あり3。
「円なのは？」を「渦巻きなのは？」に変える場合も、渦巻き1・円3へ作り直す。
正解ラベルをそのまま引き継がず、最終の描画条件から解き直す。

新しい問いの文言だけを登録するのは禁止。
各派生は、問い、図の条件、判定規則、正解、答え合わせ、確認状態を1組として持つ。
例えば「横長なのは？」は横長が1つだけある条件へ、「止まっているのは？」は静止1・移動3へ変える。

再現に必要な系統・派生・数値・並び順・生成元の番号をプレイごとに保持する。
同じ図を再確認できることが目的であり、その番号が不正防止の証明になるとは扱わない。

## 計測と比較の範囲

合計回答時間は、各問の図が描画され回答できる状態になってから最初の有効回答までの時間を合算する案。
読み込み、画面切替、解説、通信を含めない。ゲームの10問全体を単純な時計1本で計らない。
動く問題は少なくとも最初の正しいフレームを描いてから回答受付と計測を始める。
ユーザーが待って観察する時間は回答時間に含め、問題別に都合よく観察時間を差し引かない。

アプリの背景化・画面回転・描画中断があれば、同条件で時間を比べられない記録として速さの比較を保留する。
復帰時の再開・やり直しの体験は実装計画で決める。
異なる難しさのランダム問題どうしの順位が、厳密な能力差を表すとは主張しない。
オンラインランキングの方式、公開、データベース連携は別途設計する。
