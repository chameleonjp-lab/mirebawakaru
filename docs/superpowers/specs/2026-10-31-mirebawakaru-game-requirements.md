## 1. 目的と資料の位置づけ

目の錯覚を使ったイラストやアニメーションを見て、短い問いの4択に10回答えるブラウザゲームを作る。正解数を優先し、同じ正解数なら10問の合計回答時間が短い記録を上位にする。「直感力」はゲーム内の呼び方であり、知能・健康・認知能力を診断するものとは扱わない。

今回のPRは、本仕様書と[実装計画表](../plans/2026-10-31-mirebawakaru-game-implementation-plan.md)を追加する。プロダクトコードの実装、公開設定、データベースの変更は含めない。

参照したリポジトリの基準は `aa0185a3bd739275653c12aaf4b55a165b97051a`（PR #2のマージ後）。現在は資料と問題原稿があり、ゲームの入口・進行・採点・記録処理はない。

## 4. 画面と進行

| 画面・状態 | 表示と操作 | 次の状態 |
| --- | --- | --- |
| ホーム | タイトル、短い説明、「はじめる」「あそびかた」、保存済みの自己ベスト、動きを減らす設定 | 開始操作で準備へ |
| 準備 | データ・画面寸法・描画を準備。4つの回答は無効にする | 全候補の初期描画後に出題へ。失敗時は再試行かホーム |
| 出題 | 問数（例：3/10）、短い問い、対象を示す短い補足、A〜Dの4候補、4回答ボタン | 最初の有効回答で記録し、次の準備または結果へ |
| 中断 | 中断理由、「参考記録で続ける」「最初から」「ホームへ」 | 続行では現在の問題を初期状態から描き直す |
| 結果 | 正解数/10、合計回答時間、自己ベストとの比較、参考記録なら理由、「答え合わせ」「もう一度」「ホーム」 | 答え合わせまたは新規プレイ |
| 答え合わせ | 全10問の問い、自分の選択、正解、各問の時間、元の図、背景を除くなどの確認操作 | 前後の問題へ移動、結果へ戻る |

回答を確定した後は変更できない。二重タップや前の問題で押し始めた操作を次の問題に引き継がない。図そのもののタップは回答として扱わず、回答ボタンの通常の押下完了で確定する。画面切替中の入力は無視する。

Q32は例外として、図の初期描画後から計時を開始するが、初回の印を実際に描くまでは回答ボタンを無効にし「印が光ったら選べます」と示す。初回の印の状態を保存した後に回答を受け付ける。印が出る前の操作を予約回答として保持しない。

制限時間、回答スキップ、途中の正誤演出は初回には設けない。正解数の減点や速さを足した総合点は作らない。途中終了と再読み込みでは未完了の記録を保存せず、ホームから新しく始める。再開保存は初回の対象外とする。

## 5. 問題と作図の仕様

### 5.1 33問の収録範囲

| ID範囲 | 分野 | 系統数 | 特に確認すること |
| --- | --- | ---: | --- |
| Q01〜Q09 | 長さ・大きさ | 9 | 飾りや脚を除く対象、面積と長さの区別、同じ表示倍率 |
| Q10〜Q16 | 傾き・形 | 7 | 画面に対する角度、直線と曲線、円と渦巻き |
| Q17〜Q21 | 明るさ・暗い点 | 5 | 影を合成した後の色、実際に追加した帯・点 |
| Q22〜Q25 | 色・色の広がり | 4 | 対象内部の最終色、赤・青・白などの判定条件 |
| Q26〜Q27 | 輪郭・境界 | 2 | 実際に描かれた線と、見えてしまう輪郭の区別 |
| Q28〜Q33 | 動き・速さ・位置 | 6 | 同じ時計、実際の座標変化、追跡用の印、光の同期 |
| 合計 |  | 33 | 全問4候補・正解1つ |

F01〜F33を系統の識別子とする。ヘリングとヴント、ヘルマン格子ときらめき格子、ホワイトとムンカーは既存原稿の分類どおりに同じ出題系統として扱う。

### 5.2 正解と表示を一致させる条件

各候補は固定の内部識別子を持ち、表示順だけを変える。正解はラベルの文字を固定して持たず、最終の作図データから求めた内部識別子を表示中のA〜Dへ変換する。原稿の `correct_label` は原稿検査の基準であり、画面の固定正解にはしない。

最大・最小・条件一致・0以外の値を使う判定を扱い、正解候補数が1以外なら出題しない。色は問題データの `fill_rgb` と色の条件を検査する。最大の赤成分を持つ候補を無条件に「赤」とするような別の判定に置き換えない。

比較する4候補を個別に拡大縮小しない。共通の作図単位と表示倍率を使う。水平・垂直の基準は画面に固定し、端末の回転後に角度の意味を変えない。面積を問う問題で、線の太さや影まで含めた見かけの面積を判定値にしない。

対象色は、透明度・影・合成を適用した後の内部色を基準にする。背景を消す答え合わせで対象の色や寸法を塗り直して正解に合わせてはならない。検査では輪郭のなめらかさのために混ざる端の画素を避け、内部の均一な領域を確認する。端末の実測輝度を測ったとは説明しない。

ラベル、目印、余白、線の太さ、背景の濃さに正解だけの規則が生じないようにする。意図した判定対象以外の手がかりで答えられる場合は修正する。見た目の差が潰れる問題は、数値上の正解が1つでも採用しない。

### 5.3 動く6問

4候補は1つの描画ループと同じ経過時間で更新する。1フレームごとに一定量を加算する方式ではなく、経過時間から座標を求める。描画の遅れを補うために回答時間を短くしない。

| 問題 | 固有の条件と答え合わせ |
| --- | --- |
| Q28 | 実際の角速度が0以外なのは1候補。全候補の同じ2時刻の状態を重ねて確認する |
| Q29 | 中央模様の座標を往復させるのは1候補。振幅0の3候補を固定基準で確認する |
| Q30 | 枠と点の座標を分ける。画面基準で点が動く候補を1つにし、枠だけを消して確かめる |
| Q31 | 方向コードは右=1、下=2、左=3、上=4。模様に固定した印の位置を追える区間を作る。切り抜きや折返しが別方向に見える瞬間を判定根拠にしない |
| Q32 | 初回600ミリ秒後、以後1800ミリ秒ごとに4候補を同時に提示する。速度40、点の半径6、印の線幅2、提示80ミリ秒、ずれは-24・24・36・0の基本値を維持する |
| Q33 | 一定速度の4候補を同じ経過時間で比べる。共通の2時刻の始点と到達点を示す。領域端の戻り動作を速さの手がかりにしない |

Q32は、予定時刻を過ぎた最初の描画フレームで印の位置と点の位置を同時に確定し、そのフレームの状態を保存する。80ミリ秒はその実提示開始から数える。正解の点と印は提示中も重なり、誤答は提示中に重ならない条件を座標から検査する。再提示の時刻も4候補共通とし、初回や再提示を待つ時間を回答時間に含める。

Q28とQ33の確認用の2状態は、出題時に固定したモデルから全候補共通のt=0とt=1000ミリ秒を再生成する。回答が1000ミリ秒より早くてもこの確認図を使える。これは説明のための再現図であり、プレイ中にその2状態を実際に見せたと説明しない。Q32はこの方法で予定フレームを作らず、保存した最初の実提示状態を使う。

ここでの描画フレームはブラウザに描画を渡した時点を指す。画面の物理的な発光時刻や入力遅延を測定できたとは扱わない。初回未描画、描画例外、または動く問題のフレーム間隔が100ミリ秒を超えた場合は比較可能な記録から外す。この100ミリ秒は実装上の提案値であり、公開前の端末確認で変更する場合は版番号と根拠を残す。

## 6. 出題とバリエーション

通常プレイの対象は確認済みの問題だけにする。系統の一覧を同じ確率で並べ替えて先頭10系統を選び、各系統内の確認済みの派生から1つ選ぶ。分野別の固定配分、正解位置A〜Dの強制的な均等化、直前の成績による難度変更は初回には行わない。

基本形だけの第1段階でも、系統・出題順・候補順を変える。基本形の4つの作図条件と問いは変更しない。候補順を変えるときは、背景・対象・説明・判定値をひとまとまりで移す。共有する背景内の配置が錯視に必要な問題では、その条件を守る配置だけを登録する。安全に入れ替えられない配置を無理に生成しない。

第2段階では各系統に1つ以上の確認済みの派生を足す。問い、描画条件、正解、説明を一緒に定義する。少なくとも各系統の追加形では基本形から問いまたは判定対象の実値を変え、対応可能な系統では背景色や配置も変える。単なるラベル入替えを新しい派生数に数えない。

「線があるのは？」から「線がないのは？」へ変えるなら、線あり1・なし3から、あり3・なし1へ図も組み直す。正解だけを差し替えたり、背景を変えて固定の答えを繰り返したりしない。自由な数値を無制限に生成せず、確認済みの有限の組み合わせを登録する。

問題データの版、出題規則の版、記録規則の版を別々に持つ。同じ乱数の開始値だけに依存せず、実際に採用した10問の完全な描画条件も保存する。再現用の値は不正防止の証明にはならない。

## 7. 時間・採点・自己ベスト

`correctCount` は0〜10の整数。`totalAnswerMs` は全10問の回答時間を足してから、1ミリ秒単位の整数に丸める。問題ごとに丸めてから足さない。表示は秒で小数点以下3桁にする。

比較順は `(正解数の降順, totalAnswerMsの昇順)` とする。例：8問正解・30秒は、7問正解・10秒より上位。正解数もミリ秒単位の合計時間も同じなら同点にし、先着順などを追加しない。

単調に増える時計 `performance.now()` を使う。各問は全候補の初期描画を終え、次の描画機会で回答受付を有効にするときに計測を開始する。読み込み・画面切替・解説・通信は含めず、観察のために待つ時間は含める。最初の有効な回答イベントの受理時刻で停止する。問題準備中や二重入力の時間は加算しない。

Q32だけは、初期描画を終えた次の描画機会をt=0として計時を始め、初回の印を実提示し状態を保存した後に回答ボタンを有効にする。599ミリ秒までの回答は受理せず、初回実提示後の回答には開始からの待ち時間を含める。ボタンが無効な時間だけを差し引かない。

正誤は回答時に内部で確定し、結果画面まで隠す。途中の正答率や正解色を表示して次の回答へ影響させない。10問の記録は問題ごとの選択・正誤・時間から再集計し、表示中の合計値だけを保存しない。

自己ベストの対象は、中断なく10問を完了した通常プレイのみ。同じ出題・記録規則の版で比較し、版が違う過去記録は別枠に保持して混ぜない。記録する内容は、版、完了日、10問の再現情報、選択、正誤、各問の時間、合計、比較対象外の理由とする。参考記録は結果と答え合わせに使うが、自己ベストを置き換えない。

保存はブラウザ内の保存領域 `localStorage` を使う提案とする。最新の完了記録1件と、版ごとの自己ベストを最大5件保持する。保存が拒否された場合は「この端末に記録を保存できませんでした」と表示し、現在の結果は見られるようにする。破損データは実行せず、該当する保存データだけを無視する。他のアプリの保存領域は消さない。

## 8. 中断と失敗時の動作

| 条件 | 動作 | 記録の扱い |
| --- | --- | --- |
| 出題中に背景化・画面回転・比較領域の寸法変更 | 時計と動きを止め、中断画面へ。通常のブラウザバーの変化だけで作図領域が不変なら中断不要 | そのプレイは参考記録へ変更し、通常記録へ戻さない |
| 動く問題で100ミリ秒超の描画間隔、描画例外 | 中断理由を表示。描画例外は再試行成功後にだけ続行可 | 参考記録として続行可 |
| 参考記録で続行 | 過去に確定した回答を保持し、現在の問題を初期状態から再提示 | その問題の計測は0からやり直す。結果に「中断あり・時間は参考」を表示 |
| 準備前の回転 | 準備をやり直してから出題 | 計測前なので比較対象のまま |
| 不正な問題データ・正解が0または複数 | ゲーム開始前に除外し、理由を開発者向けの確認資料に残す | 有効な系統が10未満なら開始不可。プレイ途中に別問へすり替えない |
| 再読み込み・ホームへ終了 | ホームへ戻す。新しい乱数の開始値でやり直す | 未完了記録で自己ベストを更新しない |

出題開始後のデータ更新や派生の差し替えは行わない。結果と答え合わせでは、そのプレイで保存した図の条件を使う。

## 9. iPhoneでの表示と配慮

縦では問い、比較図、2列の回答ボタンを上から並べ、横では比較図と操作欄を横に分ける案とする。4候補は常に同じ画面内に置く。目標の確認寸法はCSSピクセルで402×700、393×852、852×393とし、iPhone 17 Proの実際に使用できる表示寸法も別に記録する。この数値を機種の物理仕様とは扱わない。

回答ボタンは最低44×44 CSSピクセル、問いは20ピクセル以上、補足・ボタン文字は16ピクセル以上を目標にする。画面端の操作しにくい領域を避け、横スクロールを出さない。図の比較にはスクロールを要求しない。拡大操作を一律に禁止せず、比較中に作図領域が変わる場合は参考記録へ移す。

色の問いは原稿どおりに残す。色を見分ける設定や端末の色調整によって難しさが変わることを短く案内し、成績を診断に使わない。端末の色調整を自動で検出できるとは説明しない。動きを減らす設定・端末の動き軽減設定が有効なら、静止問題だけの10問の練習とし通常の自己ベストは更新しない。静止の確認済み系統が10未満なら練習開始不可とする。

音・背景音楽は初回の必須機能にせず、音なしで成立させる。アニメーションを止める操作と、気分が悪いときにホームへ戻る操作を用意する。止めた後に通常記録の計測だけを再開しない。通常のボタン要素と文字のラベルを使うが、この視覚ゲームを視覚なしでも同条件で競えるものとは説明しない。

## 10. 実装で必要なデータの区分

| 区分 | 必要な内容 |
| --- | --- |
| 原稿 | 既存JSON。問い、判定値、場面、出典、未確認の状態を保持する |
| 実行用の問題 | 系統・問題・派生の識別子、問いと補足、4候補の作図条件、判定規則、答え合わせ条件 |
| 採用状態 | 原稿検査・描画検査・4択の見え方・iPhone縦・iPhone横・動く問題の確認結果と根拠。単一の真偽値だけで済ませない |
| 1問の出題 | 固定した作図条件、候補順、正解の内部識別子、再現用の値、必要な同時刻の状態 |
| 1プレイの記録 | 全10問の出題と回答、各時間、版番号、比較対象可否と理由、合計 |

既存JSONをそのまま実行用データとして読み込むだけでは、描画が完成したとは扱わない。通常画面には正解や内部の判定値を表示せず、答え合わせでだけ根拠を開く。ブラウザへ配るデータの正解を完全に隠せるとは主張しない。

## 12. 今回の範囲と後続の判断

この仕様に基づく最初の実装対象は、33問の描画と答え合わせ、10問の進行、正解数と時間の比較、この端末の記録、iPhoneの表示確認まで。その採用後に派生追加へ進む。

オンラインランキング、他者と同じ10問で競うモード、登録名、共有ボタン、音楽、多言語化、広告・課金は別の追加要件とする。無料公開の方針を前提とし、有料サービスや追加費用のある実行は別途の明示指示なしに開始しない。

仕様書のPRをマージすることは、ゲームの公開やデータベース変更の承認とは扱わない。実装の成果は後続PRでレビューできる状態にし、mainへの直接変更、代理マージ、自動マージの有効化は行わない。

## 13. 文書レビューで反映したこと

別担当の確認で、Q32の初回提示より前に回答すると、答え合わせに必要な実提示状態が存在しない問題が見つかった。Q32は待ち時間を計時しながら、初回実提示まで回答受付を無効にする案へ修正した。実装計画にも提示前・提示後の境界テストを追加した。

作成者の見直しでは、Q28・Q33の短時間回答でも確認図を作れるよう、共通の2時刻をモデルから再生成する条件を補った。文書レビューは描画や実機の検証を代替しない。
