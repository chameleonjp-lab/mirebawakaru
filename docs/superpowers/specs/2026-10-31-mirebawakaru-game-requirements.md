## 1. 目的と資料の位置づけ

目の錯覚を使ったイラストやアニメーションを見て、短い問いの4択に10回答えるブラウザゲームを作る。正解数を優先し、同じ正解数なら10問の合計回答時間が短い記録を上位にする。「直感力」はゲーム内の呼び方であり、知能・健康・認知能力を診断するものとは扱わない。

現在の実装対象は、第1段階の「基本33問の仕組み確認」である。正解が一意か、4択として見分けられるか、錯視としての見え方があるか、答え合わせで確かめられるかを先に確認する。成績保存・自己ベスト・ランキング・派生追加はこの段階に含めない。

PR #3は本仕様書と実装計画表だけを追加した資料PRである。今回の追加依頼では、T01〜T06・T08・初期T10の実装と、GitHub Pages／Actionsによる確認用ページの初回・継続公開準備を行う。データベースは接続しない。

参照したリポジトリの基準は `aa0185a3bd739275653c12aaf4b55a165b97051a`（PR #2のマージ後）。現在は資料と問題原稿があり、ゲームの入口・進行・採点・記録処理はない。

## 4. 画面と進行

| 画面・状態 | 表示と操作 | 次の状態 |
| --- | --- | --- |
| ホーム | タイトル、「33問の確認用」の表示、「10問を試す」「問題を指定して確認」「あそびかた」、動きを減らす設定。自己ベストは表示しない | 指定した問題の確認、または10問の準備へ |
| 準備 | データ・画面寸法・描画を準備。4つの回答は無効にする | 全候補の初期描画後に出題へ。失敗時は再試行かホーム |
| 出題 | 問数（例：3/10）、短い問い、対象を示す短い補足、A〜Dの4候補、4回答ボタン | 最初の有効回答をメモリー内に保持し、次の準備または結果へ |
| 中断 | 中断理由、「確認を続ける」「最初から」「ホームへ」 | 続行では現在の問題を初期状態から描き直す。時間は参考扱い |
| 結果 | その場の正解数/10、合計回答時間、「結果は保存しません」、中断時の理由、「答え合わせ」「もう一度」「ホーム」 | 答え合わせまたは新規プレイ。ホームや再開始で一時データを破棄 |
| 答え合わせ | 全10問の問い、自分の選択、正解、各問の時間、元の図、背景を除くなどの確認操作 | 前後の問題へ移動、結果へ戻る |

回答を確定した後は変更できない。二重タップや前の問題で押し始めた操作を次の問題に引き継がない。図そのもののタップは回答として扱わず、回答ボタンの通常の押下完了で確定する。画面切替中の入力は無視する。

Q32は例外として、図の初期描画後から計時を開始するが、初回の印を実際に描くまでは回答ボタンを無効にし「印が光ったら選べます」と示す。初回の印の状態を保存した後に回答を受け付ける。印が出る前の操作を予約回答として保持しない。

単問を指定する確認画面では、問題IDでQ01〜Q33を選び、原図と答え合わせを何度でも確認できる。不正なデータや描画不能の問題は理由を表示し、別問へ黙って置き換えない。この単問確認は10問プレイの回答済み状態や成績には混ぜない。

制限時間、回答スキップ、途中の正誤演出は初回には設けない。正解数の減点や速さを足した総合点は作らない。途中終了と再読み込みでは未完了の記録を保存せず、ホームから新しく始める。再開保存は初回の対象外とする。

### 5.1 33問の収録範囲

| ID範囲 | 分野 | 系統数 | 特に確認すること |
| --- | --- | ---: | --- |
| Q01〜Q09 | 長さ・大きさ | 9 | 飾りや脚を除く対象、面積と長さの区別、同じ表示倍率 |
| Q10〜Q16 | 傾き・形 | 7 | 画面に対する角度、直線と曲線、円と渦巻き |
| Q17〜Q21 | 明るさ・暗い点 | 5 | 影を合成した後の色、実際に追加した帯・点 |
| Q22〜Q25 | 色・色の広がり | 4 | 対象内部の最終色、赤・青・白などの判定条件 |
| Q26〜Q27 | 輪郭・境界 | 2 | 実際に描かれた線と、見えてしまう輪郭の区別 |

F01〜F33を系統の識別子とする。ヘリングとヴント、ヘルマン格子ときらめき格子、ホワイトとムンカーは既存原稿の分類どおりに同じ出題系統として扱う。

### 5.2 正解と表示を一致させる条件

各候補は固定の内部識別子を持ち、表示順だけを変える。正解はラベルの文字を固定して持たず、最終の作図データから求めた内部識別子を表示中のA〜Dへ変換する。原稿の `correct_label` は原稿検査の基準であり、画面の固定正解にはしない。

最大・最小・条件一致・0以外の値を使う判定を扱い、正解候補数が1以外なら出題しない。色は問題データの `fill_rgb` と色の条件を検査する。最大の赤成分を持つ候補を無条件に「赤」とするような別の判定に置き換えない。

比較する4候補を個別に拡大縮小しない。共通の作図単位と表示倍率を使う。水平・垂直の基準は画面に固定し、端末の回転後に角度の意味を変えない。面積を問う問題で、線の太さや影まで含めた見かけの面積を判定値にしない。

対象色は、透明度・影・合成を適用した後の内部色を基準にする。背景を消す答え合わせで対象の色や寸法を塗り直して正解に合わせてはならない。検査では輪郭のなめらかさのために混ざる端の画素を避け、内部の均一な領域を確認する。端末の実測輝度を測ったとは説明しない。

ラベル、目印、余白、線の太さ、背景の濃さに正解だけの規則が生じないようにする。意図した判定対象以外の手がかりで答えられる場合は修正する。見た目の差が潰れる問題は、数値上の正解が1つでも採用しない。

### 5.3 動く6問

4候補は1つの描画ループと同じ経過時間で更新する。1フレームごとに一定量を加算する方式ではなく、経過時間から座標を求める。描画の遅れを補うために回答時間を短くしない。

| 問題 | 固有の条件と答え合わせ |
| --- | --- |
| Q28 | 実際の角速度が0以外なのは1候補。全候補の同じ2時刻の状態を重ねて確認する |
| Q29 | 中央模様の座標を往復させるのは1候補。振幅0の3候補を固定基準で確認する |
| Q30 | 枠と点の座標を分ける。画面基準で点が動く候補を1つにし、枠だけを消して確かめる |
| Q31 | 方向コードは右=1、下=2、左=3、上=4。模様に固定した印の位置を追える区間を作る。切り抜きや折返しが別方向に見える瞬間を判定根拠にしない |
| Q32 | 初回600ミリ秒後、以後1800ミリ秒ごとに4候補を同時に提示する。速度40、点の半径6、印の線幅2、提示80ミリ秒、ずれは-24・24・36・0の基本値を維持する |
| Q33 | 一定速度の4候補を同じ経過時間で比べる。共通の2時刻の始点と到達点を示す。領域端の戻り動作を速さの手がかりにしない |

Q32は、予定時刻を過ぎた最初の描画フレームで印の位置と点の位置を同時に確定し、そのフレームの状態を保存する。80ミリ秒はその実提示開始から数える。正解の点と印は提示中も重なり、誤答は提示中に重ならない条件を座標から検査する。再提示の時刻も4候補共通とし、初回や再提示を待つ時間を回答時間に含める。

Q28とQ33の確認用の2状態は、出題時に固定したモデルから全候補共通のt=0とt=1000ミリ秒を再生成する。回答が1000ミリ秒より早くてもこの確認図を使える。これは説明のための再現図であり、プレイ中にその2状態を実際に見せたと説明しない。Q32はこの方法で予定フレームを作らず、保存した最初の実提示状態を使う。

ここでの描画フレームはブラウザに描画を渡した時点を指す。画面の物理的な発光時刻や入力遅延を測定できたとは扱わない。初回未描画、描画例外、または動く問題のフレーム間隔が100ミリ秒を超えた場合は中断して時間を参考扱いにする。この100ミリ秒は実装上の提案値であり、公開前の端末確認で変更する場合は版番号と根拠を残す。

## 6. 出題とバリエーション

### 6.1 まず33問を確認する

最初は「確認用」の画面と単問の確認用一覧を作る。数値検査が通った基本形は、錯視の見え方やiPhone確認が未完了でも、確認対象として表示できる。未確認を合格にするのではなく、確認するために見られるようにする。採用状態が要修正・保留の問題も、数値・描画の安全条件を満たす範囲で単問確認できる。

確認用の10問プレイは、数値検査を通った異なる系統を等確率で並べ替えて先頭10系統を選ぶ。有効な系統が10未満なら10問プレイは開始せず、単問で確認する。正解が0または複数の問題は確認用でも回答問題として出さず、一覧でエラーを表示する。

系統・出題順・候補順だけを変え、基本形の4つの作図条件と問いは変更しない。候補順を変えるときは背景・対象・説明・判定値をひとまとまりで移す。配置が錯視に必要な問題では、条件を守る配置だけを使う。分野別の固定配分や成績に応じた難度変更は行わない。

### 6.2 問題がなかった種類だけを本番向けに増やす

33問の確認結果を整理した後、本番で使うのは採用可の種類だけとする。要修正・保留は本番の抽選と派生追加から外し、修正して再確認した後に採用できる。未確認の種類を目標数のために合格へ変更しない。

本番用も1プレイ10問・同じ系統の重複なしを守るため、採用可の系統が10未満なら本番用10問プレイは成立しない。確認用の単問表示は続けられる。派生の数だけを増やして、系統の不足を埋めた扱いにしない。

追加する種類と派生数は確認結果を見て決める。基本33系統すべてに問題がなかった場合に限り、各1派生を足した計66形という案を検討できる。33系統の一部に問題がある場合、33系統全部から66形へ増やすことを前提にしない。

問い・描画条件・正解・説明を一緒に定義する。基本形から問いまたは判定対象の実値を変え、対応する背景色・配置も条件に合わせて変える。ラベル入替えだけは新しい派生に数えない。親の基本形が採用可でも、派生は描画・一意性・見え方・iPhone縦横・必要な動きを別に確認する。

「線があるのは？」から「線がないのは？」へ変えるなら、線あり1・なし3から、あり3・なし1へ図も組み直す。正解だけを差し替えたり、背景を変えて固定の答えを繰り返したりしない。自由な数値を無制限に生成せず、確認した有限の組み合わせを登録する。

本番用は採用可の系統を先に選び、その系統内の確認済みの派生から選ぶ。派生が多い系統を出やすくしない。問題データの版と出題規則の版は別に持ち、実際に出した図の完全な条件をその場の答え合わせまでメモリー内で保持する。初期段階では再現情報を端末やサーバーへ保存しない。

## 7. その場の採点・時間と、本番準備での記録

### 7.1 初期段階は一時表示だけにする

正解数と回答時間は、10問の仕組みを確かめるため、そのプレイ中だけメモリー内で扱う。完了後の答え合わせも同じ一時データを使う。自己ベスト、プレイ履歴、登録名、ランキングは初期段階に作らない。

成績や再現情報を localStorage、sessionStorage、IndexedDB、Cookie、サーバー、解析サービスへ保存・送信しない。ホームへ戻る、新しいプレイを始める、再読み込みする操作で、その場の回答・時間・作図条件を破棄する。永続化しないという意味であり、現在の図の状態や選択を答え合わせまで一時保持することは必要とする。

作業の確認根拠として残す「問題ごとの採用可・要修正・保留とその理由」は、プレイヤーの成績とは別の開発資料である。これらの確認表・テスト結果を作成する作業は継続する。

### 7.2 採点と時計の仕組み

correctCount は0〜10の整数。totalAnswerMs は全10問の回答時間を足してから、1ミリ秒単位の整数に丸める。問題ごとに丸めてから足さない。表示は秒で小数点以下3桁にする。

比較規則は (正解数の降順, totalAnswerMsの昇順) とする。例：8問正解・30秒は7問正解・10秒より上位。正解数も整数ミリ秒の合計時間も同じなら同点。初期段階はこの計算の検査とその場の表示までにし、過去記録との比較や保存は作らない。

単調に増える時計 performance.now() を使う。各問は全候補の初期描画を終え、次の描画機会で回答受付を有効にするときに計測を開始する。読み込み・画面切替・解説・通信は含めず、観察のために待つ時間は含める。最初の有効回答の受理時刻で停止する。

Q32だけは、初期描画を終えた次の描画機会をt=0として計時を始め、初回の印を実提示して状態を一時保持した後に回答を有効にする。599ミリ秒までの入力は受理せず、実提示後の回答には開始からの待ち時間を含める。無効時間を差し引かない。

正誤は回答時に内部で確定し、結果画面まで隠す。10問の結果は問題ごとの選択・正誤・時間から再集計する。中断したプレイはその場の時間を参考扱いにする。

### 7.3 記録機能は本番準備へ移す

33問の確認結果を見て本番の出題対象を決めた後、成績の記録機能を設計・実装する。記録を本番で取る方針はユーザー決定済みである。保存先、保存項目、自己ベスト、登録名、オンラインでの順位集計などの具体方式は本番準備で決める。

従来の「初回から localStorage に最新1件・自己ベスト最大5件を保存する」案は、初期段階から外す。将来の方式としても確定扱いにしない。本番向けの記録仕様とその検査条件が定まってから、保存処理や接続先を追加する。

## 8. 中断と失敗時の動作

| 条件 | 動作 | 初期段階の結果の扱い |
| --- | --- | --- |
| 出題中に背景化・画面回転・比較領域の寸法変更 | 時計と動きを止め、中断画面へ。作図領域が不変のブラウザバー変化だけなら中断不要 | 中断あり・時間は参考と表示。成績は保存しない |
| 動く問題で100ミリ秒超の描画間隔、描画例外 | 理由を表示。描画例外は再試行成功後に続行可 | 時間は参考として続行 |
| 確認を続ける | 確定済み回答をメモリー内に保持し、現在の問題を初期状態から再提示 | 現在問の計測は0から。結果に中断理由を表示 |
| 準備前の回転 | 準備をやり直してから出題 | 計測前として扱う |
| 正解0または複数、不正データ、描画不能 | 一覧で問題IDと理由を示す。回答問題には出さない | 数値的に有効な系統が10未満なら単問確認のみ。途中で別問へすり替えない |
| 再読み込み・ホームへ終了・新規プレイ | 新しく始める | 前のプレイの一時回答・時間・作図状態を破棄 |

出題開始後にデータや派生を差し替えない。結果と答え合わせは現在のプレイで一時保持した図の条件を使う。第1段階は記録の送信・保存や保存失敗の処理を必要としない。

## 9. iPhoneでの表示と配慮

縦では問い、比較図、2列の回答ボタンを上から並べ、横では比較図と操作欄を横に分ける案とする。4候補は常に同じ画面内に置く。目標の確認寸法はCSSピクセルで402×700、393×852、852×393とし、iPhone 17 Proの実際に使用できる表示寸法も別に記録する。この数値を機種の物理仕様とは扱わない。

回答ボタンは最低44×44 CSSピクセル、問いは20ピクセル以上、補足・ボタン文字は16ピクセル以上を目標にする。画面端の操作しにくい領域を避け、横スクロールを出さない。図の比較にはスクロールを要求しない。拡大操作を一律に禁止せず、比較中に作図領域が変わる場合は中断し、時間を参考扱いにする。

色の問いは原稿どおりに残す。色を見分ける設定や端末の色調整によって難しさが変わることを短く案内し、成績を診断に使わない。端末の色調整を自動で検出できるとは説明しない。動きを減らす設定・端末の動き軽減設定が有効なら、静止問題だけの10問の確認用プレイとする。数値検査を通った静止系統が10未満なら単問で確認する。初期段階のすべてのモードで成績保存は行わない。

音・背景音楽は初回の必須機能にせず、音なしで成立させる。アニメーションを止める操作と、気分が悪いときにホームへ戻る操作を用意する。止めた後は中断扱いにし、時間だけを比較可能な状態へ戻さない。通常のボタン要素と文字のラベルを使うが、この視覚ゲームを視覚なしでも同条件で競えるものとは説明しない。

| 区分 | 必要な内容 |

## 12. 今回の範囲と後続の判断

この仕様に基づく最初の実装対象は、33問の描画・仕組み・答え合わせ、確認用の単問選択と10問進行、その場の正解数と時間、iPhoneの表示確認まで。成績保存・自己ベスト・履歴・ランキング・派生追加は含めない。

実装の基準mainは `a3ce6a9356e6db0d2499a0335c878e1946b68fd5`。最新状態を取り直してから新規ブランチで実装し、mainへの直接push・代理マージ・自動マージを行わない。ユーザー本人のマージが初回公開の契機となる。
